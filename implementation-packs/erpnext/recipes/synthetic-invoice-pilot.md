# Recipe: synthetic membership invoice

1. Finance creates an independent expected-results sheet for one synthetic customer, one approved test item, quantity, rate, any explicitly reviewed test tax, total, and expected states.
2. In isolated staging, an administrator configures only the minimum required company/accounting context and roles using current official docs.
3. An operator creates the item and synthetic customer, then a draft invoice.
4. A separate finance reviewer checks fields and totals before any submit action.
5. Exercise correction/cancellation supported by the selected configuration and record all identifiers.
6. Add only a synthetic payment reference, never card/bank credentials, and reconcile it.
7. Export records, restore the site, repeat reconciliation, and destroy pilot data under the approved rule.

Exact menus and behavior are version/localization-specific and must be verified rather than copied from this recipe.
