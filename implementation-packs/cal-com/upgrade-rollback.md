# Cal.com upgrade and rollback

## Self-hosted change

Pin current/target releases, read release and migration instructions, back up state, capture event/config inventory, and stage the upgrade. Test public page, booking, conflict, time zones, background jobs, calendar sync, email, roles, API/workflows, and export.

## Managed change

Review announced feature, plan, API, and integration changes; rerun critical booking tests and keep manual scheduling ready.

## Rollback

Unpublish the link on unexplained conflicts or privacy failures. For self-hosting, restore the previous compatible app/config/database state; never assume schema downgrade. Reconcile every affected booking and contact attendees through approved staff.

No upgrade, SaaS release response, or rollback is tested here.
