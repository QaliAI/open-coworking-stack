## Current limits

<aside class="ocs-limitations" id="not-yet-available">
  <h3>This is a decision aid, not a completed verification program</h3>
  <ul>
    <li>
      <strong>No Verified Core tools yet.</strong> Research-backlog entries are not promoted by a
      recent date or a high rank score.
    </li>
    <li>
      <strong>Task-fit coverage is partial.</strong> Cards say “Task fit not reviewed” where
      structured role, manual-process, and human-work review is absent.
    </li>
    <li>
      <strong>Guide states are literal.</strong> A planned guide is not linked or described as
      complete; a stub is identified as a stub.
    </li>
    <li>
      <strong>Builder and estimator outputs are directional.</strong> They use editable assumptions,
      not current quotes or proof of savings. No staffing reduction or payback is implied.
    </li>
    <li>
      <strong>Comparisons are directional.</strong> Re-check official licensing, pricing, security,
      and deployment sources before a production decision.
    </li>
  </ul>
</aside>

## A practical first pass

1. Name one manual task and the staff member accountable for its outcome.
2. [Filter the directory](./directory/) by role, task language, deployment, and research tier.
3. Read the human-work and confidence fields before comparing product features.
4. Run one smallest useful experiment with synthetic or low-risk data.
5. Keep an exit path and a person responsible for exceptions, security, and recovery.
