## Recommended path

1. **Name the problem** — billing chaos, tour no-shows, Wi-Fi complaints, SOP drift, etc.
2. **Pick your role lens** — [by role](../../navigation/by-role/) or [by problem](../../navigation/by-problem/).
3. **Shortlist 2–4 tools** in the [directory](../../directory/) with filters for license class and deployment.
4. **Read license class carefully** — especially `source-available`, `fair-code`, and `open-core`.
5. **Run the smallest useful experiment** on the tool page before a multi-month rollout.
6. **Check data, backups, and offboarding** — if you cannot export and restore, you do not own the process.
7. **Prefer a reference stack** over random apps that never integrate.

## What “verified” means here

Each catalog entry has a verification block with a date and sources. Fields may still be **partially verified**: for example, we confirm a project is AGPL from its repository LICENSE file, but we do not scrape live pricing tables into the catalog as hard numbers.

When something cannot be confirmed, the entry says so. Re-check official pages before production decisions.

## What this project is not

- Not a managed coworking platform
- Not legal, tax, or compliance advice ([disclaimer](../disclaimer/))
- Not a dump of upstream source code
- Not a ranking you should treat as gospel—`rank_score` is editorial prioritization for guides, not a quality certificate
